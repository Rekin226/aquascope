# Adoption release readiness

This release improves the Explorer's record-to-export and reproducible-study paths.
It must not be described as independently validated or as proven adoption growth.

## Prepared for review

- Exact estimator/interval identity, input hashes and scoped grades in browser,
  reports and workbook; annual-maxima trend for flood questions.
- Full observations preserved through CSV export, workbench transfer and upload.
- Three observed regional examples with complete files, retained CSVs and qualified
  conclusions. The short Seine record refuses the 100-year extrapolation gate.
- Source deadlines, per-station checkpoints, retained last-good data/bundles and
  explicit partial-refresh status; daily browser coverage/export checks.
- Executed quickstart, scoped validation matrix, updated paper/citation metadata,
  Explorer-first entry routes, mobile controls and local opt-in measurement.
- Draft pilot/review protocol and a real archive deposit package with file hashes.

The implementation tracker records actual tests and checks. Reference artifacts
name their analysis-code commit; a released package DOI does not identify later
unreleased changes. Preserve both the data hash and the analysis revision.

## Before calling the release operational

1. Review the integration base and adoption changes, including the independent
   scientific review requirements. Publish the reviewed code through the normal
   merge/release path and verify the Explorer serves that build.
2. Run the browser workflow against the deployed site. Inspect actual periods,
   coverage regressions, failed cases and full CSV/workbench row counts. A usable
   shorter fallback record does not prove that the historical coverage was restored.
3. Inspect the published archive revision and per-source observation/bundle status
   for two consecutive scheduled runs. A manual run or passing code test cannot
   substitute for those scheduled publications.
4. Have the independent reviewer reproduce each promoted reference from its input
   CSV and code revision; record findings and sign-off. Until then keep the pending
   label visible. Review uncertainty, daily-mean versus instantaneous peaks,
   stationarity, missingness, extrapolation and report scope.
5. Deposit the reviewed archive package through the maintainer's Zenodo account.
   Check agency rights and coverage, register the real version/concept DOI, then
   wire the real identifiers into the dataset card and citation guidance. Never
   substitute the software DOI for the data.
6. Run the consented pilot and 28-day follow-up. Count real downstream uses only
   with participant confirmation; obtain separate permission for public examples.
7. Send focused replies or release announcements only when explicitly authorized.
   The prepared drafts are not sent messages.
